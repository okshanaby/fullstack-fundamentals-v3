# SSH (Secure Shell) — Full Notes Summary

**SSH (Secure Shell)** is a secure protocol used to access and manage remote machines over a network using encrypted communication and public/private key authentication instead of passwords.

---

# 1. What SSH Is

SSH allows you to:

* Connect to remote servers securely
* Run commands on another machine
* Transfer data safely
* Avoid password-based login

---

# 2. How SSH Works (Simple Idea)

```text id="ssh01"
Your Computer (Private Key 🔒)
        ↓ encrypts / authenticates
     Internet
        ↓
Server (Public Key 🔓)
```

* Private key stays on your computer
* Public key is stored on the server
* Server verifies your identity using the key pair

---

# 3. SSH Key Types

| Type              | Meaning                     |
| ----------------- | --------------------------- |
| Public Key (.pub) | Shared with servers         |
| Private Key       | Kept secret on your machine |

---

# 4. Generate SSH Keys

## Default method

```bash id="ssh02"
ssh-keygen -t rsa -b 4096
```

### Flags:

* `-t rsa` → sets RSA encryption type
* `-b 4096` → key strength (higher = more secure)

---

## Modern recommended method

```bash id="ssh03"
ssh-keygen -t ed25519
```

### Flags:

* `-t ed25519` → modern, faster, more secure algorithm

---

## Custom location

```bash id="ssh04"
ssh-keygen -t rsa -b 4096 -f ~/.ssh/my_keys/my_key
```

### Flags:

* `-t rsa` → key type
* `-b 4096` → strength
* `-f ~/.ssh/my_keys/my_key` → file path for saving key

---

# 5. Default SSH Key Location

```text id="ssh05"
~/.ssh/
```

Typical files:

```text id="ssh06"
id_rsa       → private key
id_rsa.pub   → public key
```

---

# 6. View Public Key

```bash id="ssh07"
cat ~/.ssh/my_keys/my_key.pub
```

---

# 7. Add SSH Key to Server

## Method A (Recommended)

```bash id="ssh08"
ssh-copy-id -i ~/.ssh/my_keys/my_key.pub user@server_ip
```

### Flags:

* `-i` → specifies public key file

---

## Method B (Manual)

```bash id="ssh09"
cat ~/.ssh/my_keys/my_key.pub
ssh user@server_ip
mkdir -p ~/.ssh
chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

### Commands:

* `mkdir -p` → create directory if missing
* `chmod 700` → secure folder permissions
* `chmod 600` → secure file permissions

---

## Method C (One-line copy)

```bash id="ssh10"
cat ~/.ssh/my_keys/my_key.pub | ssh user@server_ip "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

---

# 8. Connect to Server

## Default key

```bash id="ssh11"
ssh user@server_ip
```

## Custom key

```bash id="ssh12"
ssh -i ~/.ssh/my_keys/my_key user@server_ip
```

### Flags:

* `-i` → identity file (private key path)

---

# 9. SSH Config (Recommended)

## Open config file

```bash id="ssh13"
nano ~/.ssh/config
```

## Example config

```text id="ssh14"
Host myserver
    HostName 192.168.1.10
    User ubuntu
    IdentityFile ~/.ssh/my_keys/my_key
```

### Meaning:

* `Host` → shortcut name
* `HostName` → server IP or domain
* `User` → login username
* `IdentityFile` → private key path

---

## Connect using shortcut

```bash id="ssh15"
ssh myserver
```

| Flag | Meaning                     |

# 11. Host Key Security Settings (Advanced / Troubleshooting Only)

👉 **IMPORTANT:** Only use this when SSH has connection issues or warnings.

---

## Check SSH config

```bash id="ssh16"
cat ~/.ssh/config
```

---

## Risky settings (avoid in production)

```text id="ssh17"
StrictHostKeyChecking no
StrictHostKeyChecking ask
```

### Meaning:

* `no` → auto-trusts all servers (unsafe)
* `ask` → prompts every connection

---

## Safe fix for first-time connection

```bash id="ssh18"
ssh -o StrictHostKeyChecking=accept-new -i ./fm-fullstack-v3 root@185.53.211.34
```

### Flags:

* `-o StrictHostKeyChecking=accept-new` → accept new servers and store them
* `-i ./fm-fullstack-v3` → private key file

---

## Strict security mode

```bash id="ssh19"
ssh -o StrictHostKeyChecking=yes -i ./fm-fullstack-v3 root@185.53.211.34
```

### Flags:

* `StrictHostKeyChecking=yes` → forces strict verification of server identity

---

## When to use this section

Only when:

* First-time connection prompts appear
* SSH warns about host identity changes
* Connection is blocked due to host key mismatch

---

# 12. Why SSH is Powerful

* No passwords sent over network
* Strong encryption
* Works with automation and servers
* Used in cloud, DevOps, Git, and remote systems

---

## One-Sentence Summary

**SSH is a secure remote access system that uses key-based authentication, configurable commands (`ssh-keygen`, `ssh`, `ssh-copy-id`), and optional advanced host verification settings to safely manage servers without passwords.**
