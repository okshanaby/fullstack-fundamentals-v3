# Security — Simple Summary

**Security** is the practice of protecting systems, accounts, and data from unauthorized access. One of the most common security methods is authentication using usernames and passwords, but passwords have several weaknesses if not managed properly.

## Common Password Attacks

### Dictionary Attack

A **dictionary attack** is when an attacker tries a large list of common words, phrases, and predictable passwords.

Examples:

```text
password
123456
qwerty
welcome
admin123
football
```

Because many users choose simple passwords, dictionary attacks can be very effective.

### Rainbow Table Attack

A **rainbow table** is a precomputed database of password hashes and their matching original passwords.

Example concept:

```text
password123 → hash_value_1
admin123    → hash_value_2
welcome1    → hash_value_3
```

If an attacker obtains a password hash, they can look it up in a rainbow table to quickly discover the original password.

## What is Hashing?

**Hashing** is the process of taking data and running it through a mathematical function that produces a fixed-length output called a hash.

Example:

```text
Input:
hello

Hash:
2cf24dba5fb0a...
```

Important properties of hashing:

* Same input always produces the same hash.
* Small input changes create completely different hashes.
* Hashes are fixed length.
* Used for password storage and data verification.

# Common Hashing Algorithms

## MD5

### Create an MD5 Hash with OpenSSL

```bash
echo -n "hello" | openssl md5
```

Example output:

```text
MD5(stdin)= 5d41402abc4b2a76b9719d911017c592
```

### Why MD5 is Insecure

* Fast to crack
* Vulnerable to rainbow tables
* Produces relatively short hashes
* No longer considered secure for password storage

---

## SHA-1

### Create a SHA-1 Hash with OpenSSL

```bash
echo -n "hello" | openssl sha1
```

Example output:

```text
SHA1(stdin)= aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d
```

### Notes

* More secure than MD5
* Still considered weak by modern standards
* Not recommended for password storage

---

## SHA-256

### Create a SHA-256 Hash with OpenSSL

```bash
echo -n "hello" | openssl sha256
```

Example output:

```text
SHA2-256(stdin)= 2cf24dba5fb0a30e26e83b2ac5b9e29...
```

### Advantages

* Much stronger than MD5 and SHA-1
* Longer hash output
* More resistant to attacks

---

## Why Use `echo -n`?

The `-n` option prevents a newline character from being added.

Without `-n`:

```bash
echo "hello" | openssl sha256
```

With `-n`:

```bash
echo -n "hello" | openssl sha256
```

The hashes will be different because the first command hashes:

```text
hello\n
```

while the second hashes:

```text
hello
```

## Hashing a File

You can also hash files directly.

### MD5

```bash
openssl md5 myfile.txt
```

### SHA-1

```bash
openssl sha1 myfile.txt
```

### SHA-256

```bash
openssl sha256 myfile.txt
```

Example:

```bash
openssl sha256 notes.txt
```

Output:

```text
SHA2-256(notes.txt)= 1d2f3a4b...
```

This is commonly used to verify that files have not been modified or corrupted.

## Password Strength

Longer and more complex passwords take significantly longer to crack.

| Length | Upper & Lowercase Letters Only (a-z, A-Z) | Numbers, Letters & Symbols (0-9, a-z, A-Z, %$!) |
| ------ | ----------------------------------------- | ----------------------------------------------- |
| 6      | Instant                                   | 20 Seconds                                      |
| 7      | Instant                                   | 49 Minutes                                      |
| 8      | 13 Minutes                                | 5 Days                                          |
| 9      | 6 Hours                                   | 2 Years                                         |
| 10     | 6 Days                                    | 330 Years                                       |
| 11     | 138 Days                                  | 50,000 Years                                    |
| 12     | 20 Years                                  | 8 Million Years                                 |


### Key Lesson

Adding:

* More characters
* Uppercase letters
* Lowercase letters
* Numbers
* Symbols

makes passwords dramatically harder to crack.

## Risks of Username and Password Authentication

Traditional username/password systems have several weaknesses:

* Passwords can be stolen.
* Passwords can be guessed.
* Passwords can be intercepted over a network.
* Users forget passwords.
* Users often choose predictable passwords.
* Passwords may be vulnerable to dictionary and rainbow table attacks.

---

## More Secure Alternative: SSH Keys

Instead of relying on passwords, many systems use **SSH keys** for authentication.

Benefits:

* Extremely difficult to guess.
* Much longer than passwords.
* Not vulnerable to simple dictionary attacks.
* More secure for server access.
* Eliminates the need to remember complex passwords.

### Conceptual Example

```text
User
  ↓
Private Key (secret)
  ↓
Server verifies
  ↓
Public Key
  ↓
Access Granted
```

## One-Sentence Summary

**Hashing converts data into a fixed-length value for verification and security, with OpenSSL providing tools to generate hashes such as MD5, SHA-1, and SHA-256, while stronger authentication methods like SSH keys offer better security than traditional passwords.**
