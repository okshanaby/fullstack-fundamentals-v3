# Hashing — Simple Summary

**Hashing** is a security process that converts input data into a fixed-length string called a hash. It is commonly used for verifying data integrity and securely storing passwords.

---

## What is a SALT in Cryptographic Hashing?

A **salt** is a random value added to input data *before hashing*.

### Simple idea:

```text id="s1lt01"
password + salt → hash
```

### Why SALT is used:

* Makes each hash unique even if passwords are the same
* Prevents attackers from using rainbow tables
* Makes password cracking much harder
* Adds randomness to strengthen security

### Example:

Without salt:

```text id="nosalt01"
password123 → same hash every time
```

With salt:

```text id="salt02"
password123 + X7k9 → different hash
password123 + Q2m1 → different hash
```

Even though the password is the same, the output hash changes.

---

## Practical Uses of MD5 Hashing

Even though MD5 is not secure for passwords, it still has useful applications.

### 1. File Integrity Checking

MD5 is used to confirm that a file has not been changed or corrupted during download or transfer.

Example:

```bash id="md5file01"
md5sum ubuntu.iso
```

Output:

```text id="md5file02"
5d41402abc4b2a76b9719d911017c592  ubuntu.iso
```

You compare this hash with the official hash provided by the source.

If they match → file is safe and unchanged
If they don’t match → file may be corrupted or tampered with

---

### 2. Quick Data Verification

MD5 can quickly detect changes in data.

Example use cases:

* Checking if two files are identical
* Detecting accidental file corruption
* Verifying backups

---

### Important Note

MD5 is **not secure for passwords** because:

* It is fast to compute
* It is vulnerable to rainbow tables
* It can be easily brute-forced

---

## One-Sentence Summary

**A salt adds randomness to hashes to prevent attacks like rainbow tables, while MD5 is mainly used today for verifying file integrity rather than securing passwords.**
