# Nginx Redirection & Gzip — Simple Summary

Nginx can do much more than serve web pages. Two common features are:

* **Redirection** → send users automatically to another URL.
* **Gzip Compression** → reduce file sizes before sending them to the browser, improving website performance.

---

# Nginx Redirection

A redirect tells the browser that a page has moved to a different location.

### Example Configuration

```nginx
location /help {
    return 301 https://developer.mozilla.org/en-US/;
}
```

### How It Works

When a user visits:

```text
http://yourdomain.com/help
```

Nginx immediately redirects them to:

```text
https://developer.mozilla.org/en-US/
```

---

## Understanding the Configuration

```nginx
location /help {
```

* Matches requests to `/help`.

Example:

```text
https://example.com/help
```

---

```nginx
return 301 https://developer.mozilla.org/en-US/;
```

* Returns an HTTP redirect response.
* `301` means **Permanent Redirect**.
* Browsers and search engines will remember this redirect.

---

## Common Redirect Status Codes

### Permanent Redirect

```nginx
return 301 https://newsite.com;
```

* Page has permanently moved.
* Good for SEO.

---

### Temporary Redirect

```nginx
return 302 https://newsite.com;
```

* Page has temporarily moved.
* Search engines usually keep the old URL indexed.

# Testing Nginx Configuration

Before applying configuration changes, always test them.

```bash
sudo nginx -t
```

### Breakdown

* `sudo` → run as administrator.
* `nginx` → Nginx command.
* `-t` → test configuration syntax.

Example output:

```text
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

This checks for syntax errors without restarting Nginx.

---

# Reloading Nginx

After changing configuration files:

```bash
sudo systemctl reload nginx
```

### Breakdown

* `sudo` → administrator privileges.
* `systemctl` → Linux service manager.
* `reload` → reload configuration without stopping the service.
* `nginx` → Nginx service.

Unlike restarting, reloading does not interrupt active connections.

# Gzip Compression

Gzip is a compression algorithm used by Nginx to reduce the size of files sent to browsers.

Instead of sending a large file:

```text
100 KB CSS File
```

Nginx may compress it to:

```text
20 KB - 30 KB
```

The browser automatically decompresses it after downloading.

---

## Why Use Gzip?

Benefits:

* Faster page loading
* Less bandwidth usage
* Faster API responses
* Better user experience

---

# Gzip Configuration

Located in:

```text
/etc/nginx/nginx.conf
```

Example:

```nginx
##
# Gzip Settings
##

gzip on;

# gzip_vary on;
# gzip_proxied any;
# gzip_comp_level 6;
# gzip_buffers 16 8k;
# gzip_http_version 1.1;
```

---

## Enable Gzip

```nginx
gzip on;
```

Turns Gzip compression on.

Without this setting, Nginx sends files uncompressed.

---

## Gzip Vary Header

```nginx
gzip_vary on;
```

Adds the HTTP header:

```text
Vary: Accept-Encoding
```

This helps caches know whether a compressed or uncompressed version should be served.

---

## Compress Proxied Requests

```nginx
gzip_proxied any;
```

Allows compression of responses sent through proxy servers.

Useful when Nginx sits in front of another application server.

---

## Compression Level

```nginx
gzip_comp_level 6;
```

Controls compression strength.

Range:

```text
1 = fastest, least compression
9 = slowest, most compression
```

### Recommended Production Value

```nginx
gzip_comp_level 6;
```

Why?

* Good compression ratio
* Reasonable CPU usage
* Widely used in production systems

Using:

```nginx
gzip_comp_level 9;
```

usually consumes much more CPU for only a small reduction in file size.

---

## Gzip Buffers

```nginx
gzip_buffers 16 8k;
```

Controls memory buffers used during compression.

### Meaning

```text
16 = number of buffers
8k = size of each buffer
```

Usually the default settings are sufficient.

---

## Minimum HTTP Version

```nginx
gzip_http_version 1.1;
```

Only enables compression for clients using HTTP/1.1 or newer.

Most modern browsers support this.

---

# How Compression Works

Imagine a binary sequence:

```text
00001110100000
```

Instead of storing every digit individually, compression may describe it as:

```text
4 zeros
3 ones
1 zero
1 one
5 zeros
```

This representation uses less space.

The browser can later reconstruct the original data exactly.

---

# Compression vs Hashing

These concepts are often confused.

## Compression

Goal:

```text
Reduce file size
```

Example:

```text
100 KB → 30 KB
```

Characteristics:

* Reversible
* Original file can be restored
* Designed to save bandwidth and storage

---

## Hashing

Goal:

```text
Generate a unique fingerprint
```

Example:

```text
password123
→
482c811da5d5b4bc6d497ffa98491e38
```

Characteristics:

* Not intended to reduce size
* Typically one-way
* Used for verification, security, and integrity checks

---

# Why Gzip Doesn't Help Much with Images

Most image formats are already compressed.

Examples:

* JPEG
* PNG
* WebP
* AVIF

These formats already use specialized compression algorithms.

Example:

```text
Original image: 10 MB
JPEG image: 1 MB
```

Applying Gzip:

```text
1 MB → 990 KB
```

The improvement is often very small.

Because of this, Gzip is most useful for:

* HTML
* CSS
* JavaScript
* JSON
* XML
* Text files

---

# Key Concepts Questions

### What is Gzip?

Gzip is a compression algorithm that reduces file sizes before they are sent over the network, improving website performance and reducing bandwidth usage.

---

### What Gzip compression level is recommended in production?

```nginx
gzip_comp_level 6;
```

It provides a good balance between compression efficiency and CPU usage.

---

### How does compression work?

Compression stores data in a more efficient format by describing repeated patterns instead of storing every piece of data individually.

---

### What is the difference between compression and hashing?

* **Compression** reduces size and can be reversed.
* **Hashing** creates a fingerprint and is generally not reversible.

---

### Why doesn't Gzip significantly compress images?

Image formats such as JPEG, PNG, WebP, and AVIF are already compressed, leaving very little redundant data for Gzip to remove.

## One-Sentence Summary

Nginx redirection automatically sends users to different URLs using HTTP status codes like `301`, while Gzip compression reduces the size of text-based files before transmission, improving website speed and reducing bandwidth usage.
