# CRON JOBS — Simple Summary

**Cron jobs** are a way to automatically run commands or scripts at specific times or intervals in Linux/Unix systems.

Instead of manually running tasks (like backups, deployments, or updates), cron lets the system do it for you on a schedule.

---

## Key Idea of Cron

**Cron = Scheduler for tasks**

It runs:

* scripts
* commands
* system jobs
  at fixed times (every minute, every hour, every day, etc.)

---

## What is a Cron Job?

A **cron job** is a command that runs automatically based on a schedule you define.

Example use cases:

* Auto deploy code from Git
* Run backups every night
* Clean logs every week
* Sync files every few minutes

---

## Bash Script Basics

A **bash script** is a file containing Linux commands.

It usually starts with a special line called a **shebang**:

```bash
#!/usr/bin/bash
```

### What it means:

* `#!` → tells the system this is a script
* `/usr/bin/bash` → path to the bash shell
* It ensures the script runs using bash

To find bash location:

```bash
which bash
```

---

## Viewing Cron Jobs

To open and edit cron jobs:

```bash
crontab -e
```

### What it does:

* Opens the cron configuration file
* Lets you add, edit, or delete scheduled jobs
* Each user has their own cron list

---

## Cron Syntax (Timing Format)

A cron job follows this structure:

```text
* * * * * command
│ │ │ │ │
│ │ │ │ └── Day of week (0-7)
│ │ │ └──── Month (1-12)
│ │ └────── Day of month (1-31)
│ └──────── Hour (0-23)
└────────── Minute (0-59)
```

### Example:

```bash
* * * * * echo "Hello"
```

👉 Runs every minute

---

## Understanding `2>&1`

```bash
command >> output.log 2>&1
```

### Meaning:

* `>> output.log` → send normal output (stdout) to file
* `2>` → error output (stderr)
* `&1` → merge errors into the same place as normal output

### In simple terms:

👉 “Save both success messages and errors into the same log file”

---

## Example Bash Script (Git Auto Pull)

```bash
#!/usr/bin/bash

cd /var/www/app;

echo "Pulling main branch...";
git pull origin main --ff-only;

echo "Repo is upto date :)";
```

### What it does:

* Moves into project folder
* Pulls latest code from GitHub (main branch)
* Prints status messages

---

## Example Cron Job (Run Every Minute)

```bash
* * * * * sh /var/www/app/ci-simulator.sh >> /var/www/app/ci-simulator.log 2>&1
```

### Breakdown:

* `* * * * *` → runs every minute
* `sh /var/www/app/ci-simulator.sh` → executes script
* `>> ci-simulator.log` → saves output to log file
* `2>&1` → includes errors in the same log

## Basic Workflow of Cron Jobs

1. Write a bash script
2. Make sure it works manually
3. Add it to crontab using `crontab -e`
4. Set schedule timing
5. Log output for debugging

---

## One-Sentence Summary

**Cron jobs are Linux schedulers that automatically run scripts or commands at defined time intervals, making system automation like deployments and maintenance easier and hands-free.**
