# Spinnaker — Simple Explanation

**Spinnaker** is an **open-source continuous delivery (CD) platform** used to **automate application deployments** across cloud providers and Kubernetes clusters.

In simple terms, Spinnaker helps you **deploy new versions of your application safely and automatically** without manually logging into servers.

---

# What Does Spinnaker Do?

Spinnaker automates the deployment process.

Instead of doing this manually:

```text
Developer
    │
    ▼
Build application
    │
    ▼
Copy files to server
    │
    ▼
Restart application
    │
    ▼
Verify deployment
```

Spinnaker can automate the entire workflow.

```text
Developer
    │
    ▼
Push Code
    │
    ▼
CI Tool (Build & Test)
    │
    ▼
Spinnaker
    │
    ├── Deploy to Testing
    ├── Run Verification
    ├── Deploy to Production
    └── Roll Back if Needed
```

---

# Main Features

* Automates deployments.
* Supports **Kubernetes**, Docker, and virtual machines.
* Supports multiple cloud providers.
* Performs rolling updates.
* Supports blue-green deployments.
* Supports canary deployments.
* Can automatically roll back failed deployments.

# Deployment Strategies

## Rolling Deployment

Updates servers one at a time.

```text
Server A → Update

Server B → Update

Server C → Update
```

Users continue using the application during the update.

---

## Blue-Green Deployment

Two identical environments exist.

```text
Blue Environment (Current)

Green Environment (New Version)
```

Once the new version is ready:

```text
Traffic
    │
    ▼
Green Environment
```

If something goes wrong, traffic switches back to Blue.

---

## Canary Deployment

Only a small percentage of users receive the new version first.

```text
90% → Old Version

10% → New Version
```

If everything works correctly, the deployment continues until everyone receives the new version.

* The **CI (Continuous Integration)** tool builds and tests the application.

---

# Spinnaker vs Kubernetes

| Kubernetes                                   | Spinnaker                                               |
| -------------------------------------------- | ------------------------------------------------------- |
| Runs and manages containers.                 | Deploys applications to Kubernetes and other platforms. |
| Handles scheduling, scaling, and networking. | Handles deployment pipelines and release management.    |
| Infrastructure orchestration.                | Application delivery and deployment automation.         |

They are often used **together**, not as competitors.

---

# When Would You Use Spinnaker?

Spinnaker is a good choice when you have:

* Large production applications.
* Multiple deployment environments (development, staging, production).
* Kubernetes clusters.
* Multi-cloud deployments.
* A need for safe, automated releases with rollback capabilities.
