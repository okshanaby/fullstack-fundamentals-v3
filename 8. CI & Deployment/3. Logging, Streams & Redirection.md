# Logging, Streams and Redirection — Simple Summary

Logging, streams, and redirection are core concepts in Linux/Unix systems that help you observe what your system is doing, store outputs, and control how data flows between commands and files.

---

## Logging in Linux

Linux systems automatically store important logs in a central location so you can debug issues or monitor system activity.

### Common log directory

```text
/var/log/
```

This is the main folder where system and application logs are stored.

### Common log files

* `syslog` → general system logs (system events, services, messages)
* `auth.log` → authentication logs (logins, sudo access, security events)
* `nginx/access.log` → web server request logs (requests made to your site)

---

## Viewing Logs and Files

Linux provides commands to view and inspect files, especially logs.

### Common commands

```bash
tail file.log
```

Shows the last part of a file (useful for recent logs).

```bash
head file.log
```

Shows the first page of a file.

```bash
less file.log
```

Opens a file one page at a time for easier navigation.

```bash
cat file.log
```

Displays the entire file at once.

---

## Live Log Monitoring

To watch logs in real time (very important for debugging servers):

```bash
tail -f file.log
```

This continuously shows new lines as they are added to the file.

---

## Standard Streams (How data flows in Linux)

Every Linux process uses three default data channels called streams:

### 1. Standard Input (stdin)

* Data going INTO a program
* Example: keyboard input or file input

### 2. Standard Output (stdout)

* Normal output from a program
* Example: results printed to terminal

### 3. Standard Error (stderr)

* Error messages from a program
* Example: “file not found”

---

## Redirection (Controlling data flow)

Redirection allows you to control where input/output goes instead of just the terminal.

### Common operators

### Pipe (`|`)

```bash
command1 | command2
```

* Sends **stdout of command1** into **command2**
* Used to chain commands

---

### Redirect output to file (`>`)

```bash
echo "Hello" > file.txt
```

* Writes stdout to a file
* Overwrites existing content

---

### Append output to file (`>>`)

```bash
echo "Hello again" >> file.txt
```

* Adds output to the end of a file
* Does NOT overwrite existing content

---

### Input redirection (`<`)

```bash
command < file.txt
```

* Takes input from a file instead of keyboard

---

### Redirect stderr and stdout (`2>&1`)

```bash
command > file.txt 2>&1
```

* Combines errors and normal output into one place
* Useful for full logging

## Key Concepts Questions

### What is POSIX?

```text
Portable Operating System Interface
```

It is a standard that defines how Unix-like operating systems should behave so programs can run across different systems.

---

### What are the three standard streams?

* stdin → input
* stdout → output
* stderr → errors

---

### What does `>>` do?

It appends output to a file instead of overwriting it.

---

### What command is used for live log tracking?

```bash
tail -f
```

It continuously displays new log entries as they are written.

---

## One-Sentence Summary

Logging and streams in Linux allow you to view system activity, track real-time logs, and control how data flows between commands and files using standard input, output, error, and redirection operators.
