# Subdomains in Nginx — Simple Summary

A **subdomain** is a separate section of a website that exists under a main domain.

For example:

```text
example.com        ← Main domain
blog.example.com   ← Subdomain
api.example.com    ← Subdomain
admin.example.com  ← Subdomain
```

Subdomains allow you to run different applications, services, or environments while still using the same main domain.

---

## What is a Subdomain?

A subdomain is a prefix added before a domain name.

Example:

```text
blog.example.com
```

Here:

```text
blog = subdomain
example.com = main domain
```

---

## Why Are Subdomains Useful?

Benefits:

* Separate applications under one domain
* Easier environment management
* Useful for APIs, blogs, admin panels, etc.
* No need to purchase a new domain
* Can point to different servers or applications

Examples:

```text
example.com          → Main website
blog.example.com     → Blog
api.example.com      → Backend API
admin.example.com    → Admin dashboard
```

---

# DNS Configuration (A Record)

Before Nginx can serve a subdomain, DNS must know where the subdomain points.

This is done using an **A Record**.

---

## What is an A Record?

An A Record maps a domain or subdomain to an IPv4 address.

Example:

```text
blog.example.com → 192.168.1.100
```

DNS record:

```text
Type: A
Host: blog
Value: 192.168.1.100
```

When a user visits:

```text
https://blog.example.com
```

DNS translates it to:

```text
192.168.1.100
```

and sends the request to your server.

---

# Nginx Virtual Hosts (Server Blocks)

Nginx uses **server blocks** (sometimes called virtual hosts) to determine which application should handle a request.

Typical location:

```text
/etc/nginx/sites-enabled/
```

---

## Creating a Server Block for a Subdomain

Example configuration:

```nginx
server {
    listen 80;
    listen [::]:80;

    server_name blog.example.com;

    location / {
        proxy_pass http://localhost:3000;
    }
}
```

---

## Understanding the Configuration

### Listen Directive

```nginx
listen 80;
```

Listen for HTTP traffic on port 80.

---

### IPv6 Support

```nginx
listen [::]:80;
```

Allows connections using IPv6.

---

### Server Name

```nginx
server_name blog.example.com;
```

Tells Nginx which domain or subdomain this server block should handle.

---

### Location Block

```nginx
location / {
}
```

Matches all requests starting from `/`.

Examples:

```text
/
 /about
 /posts
 /contact
```

---

### Proxy Pass

```nginx
proxy_pass http://localhost:3000;
```

Forwards requests to another application.

Example flow:

```text
Browser
    ↓
Nginx
    ↓
Node.js App (Port 3000)
```

The user accesses:

```text
blog.example.com
```

But the actual application runs on:

```text
localhost:3000
```

Nginx acts as a reverse proxy.

# Typical Steps for Creating a Subdomain

## Step 1: Create an A Record

Example:

```text
Host: blog
Type: A
Value: 192.168.1.100
```

Result:

```text
blog.example.com → 192.168.1.100
```

---

## Step 2: Create an Nginx Server Block

Example file:

```text
/etc/nginx/sites-enabled/blog
```

Configuration:

```nginx
server {
    listen 80;
    listen [::]:80;

    server_name blog.example.com;

    location / {
        proxy_pass http://localhost:3000;
    }
}
```

---

## Step 3: Test Nginx Configuration

```bash
sudo nginx -t
```

### Breakdown

* `sudo` → run as administrator
* `nginx` → Nginx command
* `-t` → test configuration syntax

Checks for errors before applying changes.

Example output:

```text
nginx: configuration file test is successful
```

---

## Step 4: Restart or Reload Nginx

Restart:

```bash
sudo service nginx restart
```

### Breakdown

* `sudo` → administrator privileges
* `service` → service management command
* `nginx` → Nginx service
* `restart` → stop and start the service again

Or reload (commonly preferred):

```bash
sudo systemctl reload nginx
```

This applies configuration changes without fully restarting the service.

## One-Sentence Summary

A subdomain is a separate section of a website (such as `blog.example.com`) that is mapped to a server using a DNS A Record and configured in Nginx using a server block containing `listen`, `server_name`, `location`, and `proxy_pass` directives.
