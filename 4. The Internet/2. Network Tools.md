# Network Tools — Simple Summary

**Network tools** help diagnose, troubleshoot, and understand network connectivity. They allow you to check whether devices are reachable, trace the path of network traffic, and inspect active network connections.

---

# 1. Ping

The **ping** command is the quickest way to check whether a host is reachable on the network.

## Example

```bash id="ping01"
ping google.com
```

### What it does

* Sends small network packets to the destination
* Waits for a reply
* Measures response time (latency)
* Confirms whether the host is reachable

---

### Sample Output

```text id="ping02"
PING google.com (142.250.190.14)

64 bytes from 142.250.190.14:
time=18 ms

64 bytes from 142.250.190.14:
time=20 ms
```

---

### What to Look For

| Result             | Meaning                     |
| ------------------ | --------------------------- |
| Replies received   | Host is reachable           |
| Request timed out  | Host may be down or blocked |
| High response time | Network may be slow         |

---

### Why Ping is Useful

* Verify Internet connectivity
* Check if a server is online
* Measure network latency
* Quickly troubleshoot connection issues

---

# 2. Traceroute

**Traceroute** shows every network hop between your computer and the destination.

## Example (Linux/macOS)

```bash id="trace01"
traceroute google.com
```

## Example (Windows)

```bash id="trace02"
tracert google.com
```

---

### What it does

* Displays every router along the route
* Shows response times for each hop
* Helps identify where delays occur

---

### Sample Output

```text id="trace03"
1  192.168.1.1       1 ms
2  ISP Router       10 ms
3  Regional Router  18 ms
4  Backbone Router  25 ms
5  Google Server    30 ms
```

---

### How Traceroute Helps Troubleshooting

If one hop suddenly becomes very slow:

```text id="trace04"
1  1 ms
2  5 ms
3  10 ms
4  400 ms
5  420 ms
```

The problem likely starts around hop 4.

This helps determine whether issues exist:

* Inside your home network
* At your ISP
* On the Internet backbone
* At the destination server

---

# 3. Netstat

**Netstat** displays network connections, listening ports, and network-related processes.

---

## View Active Connections

```bash id="net01"
netstat
```

---

## View Listening Ports

```bash id="net02"
netstat -l
```

### Flag:

* `-l` → show listening ports

---

## Show Processes Using Ports

```bash id="net03"
netstat -tulpn
```

### Flags:

* `-t` → TCP connections
* `-u` → UDP connections
* `-l` → listening ports
* `-p` → process information
* `-n` → numeric addresses (don't resolve names)

---

### Sample Output

```text id="net04"
Proto Local Address      State      PID/Program

tcp   0.0.0.0:22         LISTEN     1234/sshd
tcp   0.0.0.0:80         LISTEN     5678/nginx
```

---

### What Netstat Shows

* Open ports
* Active TCP connections
* Active UDP connections
* Connected IP addresses
* Programs using network ports

---

# Understanding Network Hops

A hop is any router or network device that forwards traffic.

Example path:

```text id="hop01"
Your Computer
      ↓
Router
      ↓
ISP
      ↓
Backbone Network
      ↓
Data Center
      ↓
Server
```

Each step is called a **hop**.

---

# Local IP Addresses

A local IP address is assigned by your router and is only used inside your local network.

Common examples:

```text id="local01"
192.168.1.10
192.168.1.20
192.168.1.50
```

---

### Typical Private IP Ranges

```text id="local02"
192.168.x.x
10.x.x.x
172.16.x.x - 172.31.x.x
```

These addresses are not accessible directly from the Internet.

# Common Troubleshooting Workflow

## Step 1: Check Connectivity

```bash id="workflow01"
ping google.com
```

If ping fails:

* Internet may be down
* DNS may be broken
* Server may be unreachable

---

## Step 2: Trace the Route

```bash id="workflow02"
traceroute google.com
```

Find where delays or failures occur.

---

## Step 3: Inspect Local Connections

```bash id="workflow03"
netstat -tulpn
```

Check:

* Open ports
* Running services
* Active connections

---

# Commands Summary

| Command           | Purpose                             |
| ----------------- | ----------------------------------- |
| `ping host`       | Check if host is reachable          |
| `traceroute host` | Show route to destination           |
| `tracert host`    | Windows version of traceroute       |
| `netstat`         | Show network connections            |
| `netstat -l`      | Show listening ports                |
| `netstat -tulpn`  | Show ports and associated processes |

---

# One-Sentence Summary

**Network tools such as `ping`, `traceroute`, and `netstat` help diagnose connectivity problems by checking whether hosts are reachable, showing the path network traffic takes, and displaying active network connections and open ports.**
