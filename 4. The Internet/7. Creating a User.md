# Users, sudo, root & SSH Access — Simple Summary

On a Linux server, users and permissions control what actions are allowed. The goal is to avoid using full **root access** all the time and instead use safer controlled access through `sudo`.

---

## Root vs sudo

**root** is the highest privilege level on a system.

* Full unrestricted access to everything in the OS
* Can modify or delete any file
* No safety checks (dangerous if mistakes happen)

**sudo** means *“super user do”*.

It allows a normal user to run specific commands with root privileges only when needed.

Example idea:

```text
root = full power always
sudo = temporary power when needed
```

This reduces risk because you are not permanently operating with full system control.

---

## Terminal Symbol (#)

When you see this in a terminal:

```text
#
```

It means you are currently logged in as **root**.

* `#` → root user (highest permission level)
* `$` → normal user

So:

```text
root@server:~#   → dangerous/high privilege mode
user@server:~$   → normal safe user mode
```

---

## Creating and Managing Users

### 1. Create a new user

```bash id="u8h2qk"
adduser your_username
```

* `adduser` → creates a new system user
* `your_username` → the name of the new account

This creates a new user with its own home directory and password setup.

---

### 2. Add user to sudo group

```bash id="3gkq1p"
usermod -aG sudo your_username
```

* `usermod` → modifies an existing user
* `-a` → append (do not remove existing groups)
* `-G sudo` → adds user to the `sudo` group

This gives the user permission to run commands as root using `sudo`.

---

### 3. Switch user

```bash id="v1k8mt"
su your_username
```

* `su` → switch user
* `your_username` → account you want to switch into

This logs you into the new user session.

---

### 4. Check sudo access

```bash id="7nq4ac"
sudo cat /var/log/auth.log
```

* `sudo` → runs command with admin privileges
* `cat` → reads and displays file content
* `/var/log/auth.log` → system log for authentication events

This tests whether the user can run admin-level commands.

---

## Enabling Login for New User (SSH Keys)

### 1. Create authorized_keys file

```text id="kq9d8s"
~/.ssh/authorized_keys
```

* `~` → home directory of the user
* `.ssh/` → hidden folder for SSH configuration
* `authorized_keys` → file that stores allowed public keys

---

### 2. Add your public key

You paste your **public SSH key** into:

```text id="h2m9fd"
~/.ssh/authorized_keys
```

This allows key-based authentication instead of passwords.

---

### 3. Exit and login with new user

```bash id="p7xq1v"
exit
```

Then:

```bash id="q8t3zn"
ssh your_username@your_IP
```

* `ssh` → secure login to remote server
* `your_username@your_IP` → new user account and server address

---

## What is `authorized_keys`?

An `authorized_keys` file stores **public SSH keys** that are allowed to access a user account.

When you try to log in:

1. Your device sends a matching **private key**
2. Server checks it against `authorized_keys`
3. If it matches → login is allowed without a password

This enables:

* Secure login
* No password needed
* Strong protection against brute-force attacks

---

## One-Sentence Summary

**Linux server setup involves creating a normal user, giving it sudo privileges for controlled root access, and enabling secure SSH login using authorized_keys instead of passwords.**
