# File Permissions & SSH Security — Simple Summary

Linux server security depends heavily on **file permissions** and **SSH configuration**. These control who can access files and how users can log into the system.

---

## File Permissions (chmod)

`chmod` is used to change file permissions.

Example:

```bash id="kq2n1d"
chmod 644 file.txt
```

* `chmod` → changes file permissions
* `644` → permission code applied to the file

### What `644` means

```text id="p9xk2a"
6   4   4
|   |   |
owner group others
```

* **Owner (6)** → read + write
* **Group (4)** → read only
* **Others (4)** → read only

So the owner can modify the file, but everyone else can only view it.

---

## SSH Configuration File

The SSH server configuration is stored in:

```text id="x2v8mq"
/etc/ssh/sshd_config
```

* `/etc/ssh/` → system directory for SSH settings
* `sshd_config` → main configuration file for SSH daemon

This file controls how SSH behaves (login rules, security settings, etc.).

---

## Security Setup Steps

### 1. Set correct permissions for SSH keys

```bash id="h3t9dp"
chmod 644 ~/.ssh/authorized_keys
```

* `chmod` → changes file permissions
* `644` → owner can read/write, others can only read
* `~/.ssh/authorized_keys` → file that stores allowed SSH public keys

This ensures the SSH key file is readable but not overly open for modification.

---

### 2. Disable root login

```bash id="a8m4rz"
sudo vi /etc/ssh/sshd_config
```

* `sudo` → runs command with admin privileges
* `vi` → terminal text editor
* `/etc/ssh/sshd_config` → SSH configuration file

Inside this file, you set:

```text id="t7q3lm"
PermitRootLogin no
```

This prevents direct SSH login as root.

---

### 3. Restart SSH service

```bash id="c9w1kp"
sudo service ssh restart
```

or

```bash id="n6xq3v"
sudo systemctl restart ssh
```

* `service` / `systemctl` → manages system services
* `ssh` → SSH daemon service
* `restart` → reloads service with new configuration

This applies the SSH configuration changes.

---

## Why disable root SSH login?

Disabling root login improves security because:

* Prevents attackers from directly targeting the root account
* Forces login using a normal user first
* Reduces risk of full system compromise
* Encourages safer use of `sudo` instead of permanent root access

---

## Viewing Authentication Logs

You can check login attempts here:

```text id="z4p8km"
/var/log/auth.log
```

To view it:

```bash id="r3k8na"
sudo cat /var/log/auth.log
```

* `cat` → displays file content
* `auth.log` → records all authentication events

This file shows:

* Successful logins
* Failed login attempts
* SSH connection activity

---

## One-Sentence Summary

**Server security is improved by setting proper file permissions with `chmod`, disabling root SSH login in `/etc/ssh/sshd_config`, restarting SSH, and monitoring login activity through `/var/log/auth.log`.**
