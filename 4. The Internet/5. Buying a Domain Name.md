# Buying a Domain Name — Simple Summary

A **domain name** is the address people use to visit your website (for example, `mywebsite.com`). To use a domain, you first buy it from a **domain registrar** and then configure it to point to your server.

## Key Points

* Buy your domain from a reliable registrar.
* Look for low prices and avoid registrars that aggressively upsell extra services.
* Useful built-in features include:

  * SSL certificates
  * Email hosting
  * Email forwarding
  * Domain privacy protection
  * Two-factor authentication (2FA)
* Some domain extensions (TLDs) are restricted and require verification.

## Choosing a Domain Registrar

When selecting a registrar, consider:

* Affordable pricing
* Easy domain management
* Domain privacy protection
* Security features (2FA)
* SSL support
* Email forwarding capabilities
* Minimal upselling

### Examples of Registrars

* Hostinger
* Namecheap
* Cloudflare
* GoDaddy

## Top-Level Domains (TLDs)

A **Top-Level Domain (TLD)** is the ending part of a domain name.

Examples:

```text
example.com   -> .com
example.org   -> .org
example.edu   -> .edu
```

### Restricted TLDs

Some TLDs can only be registered by specific organizations.

| TLD    | Used By                  |
| ------ | ------------------------ |
| `.org` | Registered organizations |
| `.edu` | Educational institutions |
| `.gov` | Government entities      |
| `.mil` | Military organizations   |

These domains usually require verification before registration.

## Nameservers

A **nameserver** tells the internet where DNS records for a domain are stored.

By default, your registrar manages DNS records.

When you change nameservers, you give DNS control to another provider such as:

* DigitalOcean
* Cloudflare

### Why Change Nameservers?

Changing nameservers allows another service to become the **authoritative DNS provider** for your domain.

Benefits:

* Easier DNS management
* Better DNS tools
* Centralized server and DNS configuration
* More flexibility

## A Records

An **A Record** connects a domain name to an IPv4 address.

Example:

```text
example.com  ---> 192.168.1.100
```

This tells browsers which server should receive requests for the domain.

### Common A Records

| Record | Purpose                                   |
| ------ | ----------------------------------------- |
| `@`    | Root domain (example.com)                 |
| `www`  | [www.example.com](http://www.example.com) |

Example:

```text
@    -> 203.0.113.10
www  -> 203.0.113.10
```

Both records point to the same server IP address.

## Domain Email Forwarding

Email forwarding lets you create custom email addresses using your domain without paying for full email hosting.

Example:

```text
support@mydomain.com
contact@mydomain.com
jobs@mydomain.com
```

These emails automatically forward messages to your main email account.

Example:

```text
support@mydomain.com
        ↓
myemail@gmail.com
```

### Benefits

* Professional appearance
* Better privacy
* Easier email organization
* Track which service received your email

## Basic Setup Process

### Step 1: Buy a Domain

Purchase a domain from a registrar.

Example:

```text
mywebsite.com
```

### Step 2: Change Nameservers

Update the domain's nameservers to point to your DNS provider.

Example:

```text
Registrar
     ↓
DigitalOcean Nameservers
```

### Step 3: Create A Records

Add two A records that point to your VPS IP address.

```text
Type    Host    Value
A       @       YOUR_SERVER_IP
A       www     YOUR_SERVER_IP
```

Example:

```text
A   @     203.0.113.10
A   www   203.0.113.10
```

## DNS Flow

```text
User visits:
www.mywebsite.com

        ↓

DNS Lookup

        ↓

A Record Found

        ↓

203.0.113.10

        ↓

Your VPS Server

        ↓

Website Loads
```

## One-Sentence Summary

**Buy a domain from a registrar, point its nameservers to a DNS provider like DigitalOcean, create A records for `@` and `www` that point to your server's IP address, and optionally use email forwarding for custom domain email addresses.**
