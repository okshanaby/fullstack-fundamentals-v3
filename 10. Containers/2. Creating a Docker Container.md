# Creating a Docker Container — Simple Summary

A **Docker container** packages your application together with its dependencies so it can run consistently on any machine that has Docker installed.

The general process is:

1. Install Docker.
2. Create a `Dockerfile`.
3. Build a Docker image.
4. Run a container from the image.
5. Verify the container is running.

---

# Step 1: Install Docker

Install Docker by following the official Docker installation guide for your operating system.

Once installed, Docker allows you to build and run containers.

---

# Step 2: Create a Dockerfile

Create a file named `Dockerfile` in the root of your application.

```dockerfile
FROM node:20-alpine

USER node

RUN mkdir -p /home/node/app

WORKDIR /home/node/app

COPY --chown=node:node package-lock.json package.json ./

RUN npm ci

COPY --chown=node:node . .

CMD ["node", "app.js"]
```

## Explanation

### Base Image

```dockerfile
FROM node:20-alpine
```

* Uses the official **Node.js 20** Docker image.
* Uses **Alpine Linux**, a lightweight Linux distribution that makes the image smaller and faster.

---

### Run as a Non-Root User

```dockerfile
USER node
```

Runs the application as the built-in `node` user instead of the `root` user for better security.

---

### Create the Application Directory

```dockerfile
RUN mkdir -p /home/node/app
```

Creates the application's working directory.

The `-p` option creates parent directories if they do not already exist.

---

### Set the Working Directory

```dockerfile
WORKDIR /home/node/app
```

All following commands are executed inside this directory.

---

### Copy Package Files

```dockerfile
COPY --chown=node:node package-lock.json package.json ./
```

Copies only the dependency files into the container.

This is done **before copying the rest of the application** to improve Docker's build cache.

If your application code changes but `package.json` doesn't, Docker can reuse the previously installed dependencies instead of reinstalling everything.

---

### Install Dependencies

```dockerfile
RUN npm ci
```

Installs dependencies exactly as specified in `package-lock.json`.

`npm ci` is preferred for production because it is:

* Faster
* More reliable
* Produces consistent installs

---

### Copy the Rest of the Application

```dockerfile
COPY --chown=node:node . .
```

Copies all remaining application files into the container.

---

### Start the Application

```dockerfile
CMD ["node", "app.js"]
```

Specifies the default command that runs when the container starts.

---

# Step 3: Build the Docker Image

```bash
docker build -t node-frontendmasterslearning-img .
```

This creates a Docker image named:

```text
node-frontendmasterslearning-img
```

---

# Step 4: Run the Container

```bash
docker run -d -p 3000:3000 --rm --name node-fmlearning-container node-frontendmasterslearning-img
```

This starts a container from the Docker image.

The application inside the container listens on port **3000**, and Docker exposes it on your computer's port **3000**.

---

# Step 5: View Running Containers

```bash
docker ps
```

Displays all currently running Docker containers.

---

# Why Use Alpine Linux?

**Alpine Linux** is commonly used in Docker because it is:

* Very lightweight
* Fast to download
* Uses minimal disk space
* Starts quickly
* Contains only the essentials needed to run applications

This results in smaller Docker images.

---

# Why Copy `package.json` First?

Instead of copying the whole project immediately, Docker first copies:

```text
package.json
package-lock.json
```

Then installs dependencies.

Benefits:

* Docker caches the installed dependencies.
* Future builds are much faster if dependencies haven't changed.
* Only application code is recopied when source files change.

---

# Why Use a Non-Root User?

Instead of running as `root`, Docker runs the application as the `node` user.

Benefits:

* Better security.
* Limits access to the operating system.
* Reduces the impact of potential vulnerabilities.

Running containers as non-root users is considered a best practice.

# Commands

## Build the Docker Image

```bash
docker build -t node-frontendmasterslearning-img .
```

**Explanation**

* `docker` – Docker command-line tool.
* `build` – Builds a Docker image from a Dockerfile.
* `-t node-frontendmasterslearning-img` – Assigns a name (tag) to the image.
* `.` – Uses the current directory as the build context.

---

## Run the Docker Container

```bash
docker run -d -p 3000:3000 --rm --name node-fmlearning-container node-frontendmasterslearning-img
```

**Explanation**

* `docker` – Docker command-line tool.
* `run` – Creates and starts a new container.
* `node-frontendmasterslearning-img` – The image to run.

---

## List Running Containers

```bash
docker ps
```

**Explanation**

* `docker` – Docker command-line tool.
* `ps` – Displays currently running containers.

---

# Command Flags

## `docker build`

| Flag | Meaning                        |
| ---- | ------------------------------ |
| `-t` | Tags (names) the Docker image. |

---

## `docker run`

| Flag                               | Meaning                                                                              |
| ---------------------------------- | ------------------------------------------------------------------------------------ |
| `-d`                               | Runs the container in detached (background) mode.                                    |
| `-p 3000:3000`                     | Maps port `3000` on the host to port `3000` inside the container (`host:container`). |
| `--rm`                             | Automatically removes the container when it stops.                                   |
| `--name node-fmlearning-container` | Assigns a custom name to the container.                                              |

---

## Dockerfile Options

### `mkdir`

| Option | Meaning                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------- |
| `-p`   | Creates parent directories if they don't exist and avoids errors if the directory already exists. |

---

### `COPY`

| Option              | Meaning                                                          |
| ------------------- | ---------------------------------------------------------------- |
| `--chown=node:node` | Sets the owner and group of the copied files to the `node` user. |

---

# Key Points

* A Dockerfile defines how a Docker image is built.
* `FROM` selects the base image.
* Alpine Linux creates smaller and faster Docker images.
* Running as the `node` user improves security.
* Copying dependency files first improves Docker layer caching and speeds up builds.
* `docker build` creates an image.
* `docker run` starts a container from the image.
* `docker ps` lists all running containers.

---

# One-Sentence Summary

**Creating a Docker container involves defining your application's environment in a Dockerfile, building it into an image, running it as a container, and using Docker's lightweight, portable architecture to ensure consistent deployment across different systems.**
