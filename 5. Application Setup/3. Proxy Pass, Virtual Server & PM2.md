# Proxy Pass, Virtual Server & PM2 — Simple Summary

This section explains how to connect a Node.js application to the internet using **Nginx as a reverse proxy**, how to configure a **virtual server (server block)**, and how to run the Node app using **PM2 (process manager)** so it stays alive.

---

## Key Idea

Instead of exposing your Node.js app directly on `localhost:3000`, you:

* Run Node.js on a private port (e.g. 3000)
* Use Nginx to receive public traffic on port 80 (HTTP)
* Nginx forwards (proxies) requests to your Node app

This setup improves:

* Security
* Performance
* Scalability
* Reliability

---

# 1. Proxy Pass (Nginx Reverse Proxy)

**Proxy pass** means Nginx forwards incoming requests to another server (your Node.js app).

So:

* User → `http://yourdomain.com`
* Nginx → forwards to `http://127.0.0.1:3000`
* Node.js → responds back through Nginx

---

## Nginx Server Configuration

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    root /var/www/html;
    index index.html;

    server_name domain_name;

    location / {
        proxy_pass http://127.0.0.1:3000/;
    }
}
```

---

## What Each Part Means

* `listen 80`
  → Accept HTTP requests on port 80 (IPv4)

* `listen [::]:80`
  → Same as above but for IPv6

* `root /var/www/html`
  → Default static files folder (HTML, assets)

* `index index.html`
  → Default file to load

* `server_name domain_name`
  → Your domain (e.g. example.com)

* `location /`
  → Match all incoming requests

* `proxy_pass http://127.0.0.1:3000/`
  → Forward requests to Node.js app running locally on port 3000

# 2. Virtual Server (Nginx Site Configuration)

A **virtual server (virtual host)** allows Nginx to host multiple websites/apps on one machine.

Each app gets its own config file.

---

## Create App Config

```bash
sudo vi /etc/nginx/sites-enabled/app_name
```

This creates a new server block for your application.

---

## How it works

* Each file in `sites-enabled/` = one website/app
* Nginx loads all enabled site configs at startup
* You can host multiple apps on different domains or ports

---

# 3. Linking Config in nginx.conf

Nginx must be told to include your site config.

```bash
sudo vi /etc/nginx/nginx.conf
```

Inside, ensure you have:

```nginx
##
# Virtual host configs
##

include /etc/nginx/conf.d/*.conf;
include /etc/nginx/sites-enabled/app_name;
```

---

## What this does

* `conf.d/*.conf` → loads general configs
* `sites-enabled/` → loads your custom app configs

This is how Nginx “knows” about your app.

---

# 4. Validate Nginx Configuration

Before restarting, always check for errors:

```bash
sudo nginx -t
```

### Meaning

* Tests Nginx configuration syntax
* Prevents broken server restart

If correct, you’ll see:

* `syntax is ok`
* `test is successful`

---

# 5. Restart Nginx

```bash
sudo service nginx restart
```

### Meaning

* Stops Nginx
* Starts it again with new config

---

# 6. Start Node.js Server (Manual)

```bash
node server
```

or usually:

```bash
node app.js
```

### Problem

If you close SSH or terminal, the app stops.

---

# 7. PM2 (Process Manager for Node.js)

This is why PM2 is used (even though not fully written in notes).

PM2 keeps Node apps running in background.

---

## Step 1. Install PM2 globally

```bash
sudo npm i -g pm2
```

## Step 2. Start app with PM2

```bash
pm2 start app.js
```

## Step 3. Setup Autorestart

```bash
pm2 save

pm2 startup
```

Copy the output command and run it

---

## Why PM2 is important

* Keeps app alive after crash
* Restarts automatically if it fails
* Runs app in background
* Allows log monitoring

---

## Useful PM2 commands

```bash
pm2 list
```

→ Shows running apps

```bash
pm2 logs
```

→ Shows logs

```bash
pm2 restart app
```

→ Restarts app

```bash
pm2 stop app
```

→ Stops app

---

# Final Flow (How Everything Works Together)

```
User Browser
     ↓
Nginx (port 80)
     ↓  proxy_pass
Node.js App (port 3000)
     ↓
Response back through Nginx
```

---

# One-Sentence Summary

**Proxy pass + virtual server setup means using Nginx as a gateway that receives web traffic and forwards it to a Node.js app running on a private port, while PM2 keeps the Node app running reliably in the background.**
