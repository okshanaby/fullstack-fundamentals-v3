# WebSockets — Simple Summary

**WebSockets** provide a **persistent (always open), bidirectional (two-way)** connection between a client (browser) and a server. Unlike HTTP, the connection stays open, allowing both the client and server to send data to each other instantly without creating a new request every time.

This makes WebSockets ideal for **real-time applications** such as chat apps, live notifications, multiplayer games, stock market updates, and live dashboards.

---

## Key Points

* WebSockets create a **persistent connection** between the client and server.
* Communication is **bidirectional**, meaning both sides can send messages at any time.
* The connection stays open until either the client or server closes it.
* WebSockets are much more efficient than repeatedly sending HTTP requests for real-time updates.
* Nginx must be configured to allow WebSocket connections.
* Express can be used alongside Node.js to make creating a WebSocket server easier.

---

# HTTP vs WebSockets

| HTTP                                       | WebSockets                                       |
| ------------------------------------------ | ------------------------------------------------ |
| One-way communication (request → response) | Two-way communication                            |
| Connection closes after every request      | Connection stays open                            |
| Client must initiate every request         | Client and server can both send messages anytime |
| Good for normal web pages and APIs         | Good for real-time applications                  |

---

## How WebSockets Work

1. The client sends an HTTP request asking to upgrade to a WebSocket connection.
2. The server accepts the upgrade request.
3. The HTTP connection becomes a WebSocket connection.
4. The connection remains open.
5. Both the client and server can exchange messages whenever needed.

# Step 1: Configure Nginx for WebSockets

Nginx needs to forward WebSocket upgrade requests to the Node.js server.

```nginx
location / {
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_pass http://127.0.0.1:3000;
}
```

### Explanation

* `location /`

  * Matches all incoming requests.

* `proxy_set_header Upgrade $http_upgrade;`

  * Passes the client's `Upgrade` header to Node.js.
  * This tells the server the client wants to switch from HTTP to WebSockets.

* `proxy_set_header Connection "upgrade";`

  * Instructs Nginx to upgrade the connection instead of treating it as a normal HTTP request.

* `proxy_pass http://127.0.0.1:3000;`

  * Forwards the request to the Node.js server running on port `3000`.

# Step 2: Create a Node.js WebSocket Server

```javascript
const express = require("express");
const server = require("http").createServer();

const app = express();

app.get("/", (req, res) => {
    res.sendFile("index.html", { root: __dirname });
});

server.on("request", app);

server.listen(3000, () => {
    console.log("Websocket Server running on port 3000");
});
```

---

## Code Explanation

### Import Express

```javascript
const express = require("express");
```

Imports the Express framework to simplify handling HTTP requests.

---

### Create an HTTP Server

```javascript
const server = require("http").createServer();
```

Creates a Node.js HTTP server that will later handle WebSocket connections.

---

### Create the Express Application

```javascript
const app = express();
```

Creates an Express application instance.

---

### Serve the Homepage

```javascript
app.get("/", (req, res) => {
    res.sendFile("index.html", { root: __dirname });
});
```

When a user visits `/`, the server sends the `index.html` file.

* `req` — The incoming request.
* `res` — The response sent back to the client.
* `__dirname` — The current project directory.

---

### Connect Express to the HTTP Server

```javascript
server.on("request", app);
```

Whenever the server receives an HTTP request, Express handles it.

---

### Start the Server

```javascript
server.listen(3000, () => {
    console.log("Websocket Server running on port 3000");
});
```

Starts listening for connections on port `3000`.

When the server starts successfully, it prints:

```text
Websocket Server running on port 3000
```

* Multiplayer games

# HTTP vs WebSockets Example

### HTTP

```text
Browser ---- Request ----> Server
Browser <--- Response ----- Server

Connection Closed
```

Every new piece of information requires another request.

---

### WebSockets

```text
Browser <=================> Server

Connection Stays Open

Client ---- Message ----> Server
Client <--- Message ----- Server
```

The same connection is reused for all communication.

# Common Interview Questions

### What is a WebSocket?

A **WebSocket** is a communication protocol that creates a **persistent, bidirectional connection** between a client and server, allowing both to exchange data in real time.

---

### What is the main difference between HTTP and WebSockets?

* **HTTP** creates a new connection for each request and closes it after sending the response.
* **WebSockets** keep a single connection open, allowing continuous two-way communication.

---

### Why must Nginx be configured for WebSockets?

Because WebSockets require upgrading an HTTP connection. Nginx must forward the required `Upgrade` and `Connection` headers so the Node.js server can establish the WebSocket connection.

---

### Why is Express used?

Express simplifies building the server by providing easy routing, request handling, middleware support, and seamless integration with WebSocket libraries.
