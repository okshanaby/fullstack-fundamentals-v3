# Supporting HTTP/2 — Simple Summary

**HTTP/2** is a newer version of HTTP that improves website performance by allowing multiple requests and responses to share a **single connection**. Compared to HTTP/1.1, it reduces connection overhead and can make web pages load faster.

## Why Use HTTP/2?

With **HTTP/1.1**, the browser often opens multiple connections to download files like HTML, CSS, JavaScript, and images.

With **HTTP/2**, all these files can be transferred over a **single connection** using a feature called **multiplexing**.

```text
HTTP/1.1

Browser
   ├── Connection 1 → HTML
   ├── Connection 2 → CSS
   ├── Connection 3 → JavaScript
   └── Connection 4 → Images
```

```text
HTTP/2

Browser
      │
      │ Single Connection
      ▼
    Server
      │
      ├── HTML
      ├── CSS
      ├── JavaScript
      └── Images
```

This reduces latency and improves overall efficiency.

---

# Enabling HTTP/2 in NGINX

Edit your NGINX site configuration.

```bash
sudo vi /etc/nginx/sites-enabled/<your-domain-or-website>
```

Locate the HTTPS `listen` directive and add `http2`.

Before:

```nginx
listen 443 ssl;
```

After:

```nginx
listen 443 ssl http2;
```

This tells NGINX to serve HTTPS traffic using HTTP/2.

---

# Test the Configuration

After making changes, verify that the NGINX configuration is valid.

```bash
sudo nginx -t
```

If there are no errors, reload or restart NGINX.

```bash
sudo service nginx restart
```

---

# Verify HTTP/2 Is Being Used

Open your website in a browser.

1. Open **Developer Tools**.
2. Go to the **Network** tab.
3. Add or view the **Protocol** column.
4. Reload the page.

You should see values such as:

```text
h2
```

or

```text
http/2
```

This confirms the browser is using HTTP/2.

# HTTP/1.1 vs HTTP/2

| Feature          | HTTP/1.1                                | HTTP/2                                           |
| ---------------- | --------------------------------------- | ------------------------------------------------ |
| Connections      | Multiple connections for multiple files | Single connection for multiple files             |
| Request Handling | One request per connection at a time    | Multiplexing allows many requests simultaneously |
| Performance      | Higher connection overhead              | Faster and more efficient                        |
| Latency          | Higher                                  | Lower                                            |
| CPU Usage        | Lower                                   | Can be higher due to multiplexing                |

---

# Advantages of HTTP/2

* Faster page loading.
* Uses fewer network connections.
* Supports multiplexing.
* Reduces latency.
* More efficient use of network resources.

---

# Potential Drawback

Although HTTP/2 improves performance, it can require **more CPU processing** because multiplexing is more complex than HTTP/1.1's connection model.

For most modern websites, the performance benefits outweigh this additional CPU cost.

# Commands

## Edit the NGINX Configuration

```bash
sudo vi /etc/nginx/sites-enabled/<your-domain-or-website>
```

**Explanation**

* `sudo` – Runs the command with administrator (root) privileges.
* `vi` – Opens the **Vi** text editor.
* `/etc/nginx/sites-enabled/<your-domain-or-website>` – Path to your NGINX site configuration file.

---

## Test the NGINX Configuration

```bash
sudo nginx -t
```

**Explanation**

* `sudo` – Runs the command with administrator privileges.
* `nginx` – Starts or manages the NGINX web server.
* `-t` – Tests the configuration files for syntax errors without restarting NGINX.

---

## Restart NGINX

```bash
sudo service nginx restart
```

**Explanation**

* `sudo` – Runs the command with administrator privileges.
* `service` – Manages system services.
* `nginx` – Specifies the NGINX service.
* `restart` – Stops and starts NGINX to apply configuration changes.

---

# Command Flags

## `nginx -t`

| Flag | Meaning                                                            |
| ---- | ------------------------------------------------------------------ |
| `-t` | Tests the NGINX configuration for syntax and configuration errors. |

The other commands (`vi` and `service`) do **not** use command flags in these examples.

---

# Key Points

* HTTP/2 allows **multiple requests and responses over a single connection** using multiplexing.
* Enable HTTP/2 by adding `http2` to the HTTPS `listen` directive in the NGINX configuration.
* Always test the configuration using `sudo nginx -t` before restarting NGINX.
* Restart NGINX to apply the changes.
* Verify HTTP/2 in your browser using the **Network** tab and checking the **Protocol** column.
* HTTP/2 generally provides better performance but may require slightly more CPU resources.

---

# One-Sentence Summary

**HTTP/2 improves web performance by allowing multiple requests and responses to share a single connection, and it can be enabled in NGINX by adding `http2` to the HTTPS `listen` directive, testing the configuration, and restarting the server.**
